**Allowed Readiness Status Values:**
- DRAFT
- IN_REVIEW
- CHANGES_REQUESTED
- APPROVED
- BLOCKED

**Allowed Review Status Values:**
- NOT_STARTED
- IN_PROGRESS
- COMPLETED

**Readiness Rules:**
- New documents must start with DRAFT.
- Testers change the document to IN_REVIEW when review begins.
- If modifications are needed, use CHANGES_REQUESTED.
- Set APPROVED only after manual tests are reviewed and approved.
- Use BLOCKED when critical requirements or technical details are unresolved.
- Document approval does not automatically approve every test case.
- The API Automation Agent must respect both document-level and
  test-case-level readiness statuses.

- [ ] Detailed execution steps are documented.
- [ ] Every API request has its own microservice and deployment type.
- [ ] Correct Swagger is referenced for each API request.
- [ ] Request payloads are stored and referenced correctly.
- [ ] API request sequence and dependencies are explicit.
- [ ] Dynamic data extraction and reuse are documented.
- [ ] DB validation is explicitly marked Yes or No for every API step.
- [ ] Splunk validation is explicitly marked Yes or No for every API step.
- [ ] Other validations are explicitly marked Yes or No for every API step.
- [ ] No undocumented business rules or assertions are invented.
- [ ] Missing or contradictory information is recorded as a blocker.
- [ ] ALM Octane summary and detailed specifications are consistent.
- [ ] Initial document readiness is DRAFT.
